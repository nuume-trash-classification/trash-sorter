# 手機 demo：正確 / 錯誤回饋與存檔（#41）

## 為什麼

學長的想法：模型的指標（mAP50）看不出實際意義，想直接拿手機拍、當場看模型答對還是答錯。
答錯的照片連同模型的預測存下來，之後修標註就能併入微調集，不用重拍。

拍照、上傳、辨識、回傳結果圖已經在 #33 做完（`perception/phone_demo.py`）。這裡只加回饋與存檔。

## 目標 / 不做的事

- 做：每張照片存原圖 + 預測標籤 + 紀錄；頁面上按「正確 / 錯誤」；關伺服器時印統計。
- 不做：在手機上修標註（畫輪廓、改類別）。一張照片有多個物體，手機上不好操作；修標註回電腦用 Roboflow。
- 不可以：把這批照片放進測試集。被標成錯誤的照片是專挑模型不會的，拿來評分會失真。只能進微調集。

## 考慮過的做法

1. **只按對錯，伺服器存預測當預標註（採用）**：手機端最簡單，錯的照片回電腦修時輪廓已經在上面。
2. 手機上點輪廓改類別：能當場修「輪廓對、類別錯」，但漏抓與輪廓歪掉還是要回電腦。先不做，看實際哪種錯誤多再說。
3. 手機上完整標註：手機畫多邊形不實際。

## 設計

- 存檔位置：`data/real/feedback/<YYYY-MM-DD>/<verdict>/`，`verdict` 是 `unreviewed`、`correct`、`wrong`。
  每個資料夾裡有 `images/<id>.jpg`、`labels/<id>.txt`、`meta/<id>.json`、`data.yaml`（類別名稱）。
  `data/` 不進 git。
- 照片：存手機上傳的原始位元組（頁面已縮到長邊 1600 px 的 JPEG），不重新壓縮。
- 標籤：YOLO-seg 格式，取自 ultralytics 的 `result.masks.xyn`（已換算回原圖的正規化多邊形）。
  不用 `masks.data` 直接縮放，因為它是補過邊的模型輸入尺寸，長寬比不合時會歪。
- 紀錄（meta）：id、時間、權重檔、conf、imgsz、偵測結果、verdict。
- `POST /predict` 的回覆多一個 `id`；新的 `POST /feedback`（JSON：`id`、`verdict`）把該照片的三個檔案搬到對應資料夾。
  可以改判（正確 ↔ 錯誤）。`id` 用固定格式檢查，不接受路徑字元。
- 頁面：結果下方「正確」「錯誤」兩個按鈕，按過會顯示已記錄。
- 參數：`--save-dir`（預設 `data/real/feedback`）、`--no-save`（不存檔，頁面也不顯示按鈕）。
- 停止伺服器時印出這次的正確 / 錯誤 / 未判定張數。這個比例是「整張照片全對」的比例，受拍攝內容影響，不能取代 mAP50。
