# 系統設計（已定案）

> 完整設計文件：<https://claude.ai/artifact/77ocPo8TJWUckUWBFbdHup>。本頁是 repo 內的中文副本，以本頁與程式碼為準。

## 目標

在 Isaac Sim 裡做一條**輸送帶垃圾分類系統**。**只做模擬，沒有實體機器人。**
用兩件事證明「模擬到真實（sim-to-real）」的能力：

- **(B) 只用合成影像訓練的 YOLO**，拿去評估**真實手機照片**（指標：mask mAP50）。
  並比較「只用模擬資料」與「模擬 + 少量真實資料微調」兩個模型。
- **(C) 即時 webcam demo**。

## 類別（4 類，只處理硬質物體）

| 類別 id | 名稱 | 說明 |
|---|---|---|
| 0 | `pet_bottle` | 寶特瓶 |
| 1 | `aluminum_can` | 鋁罐 |
| 2 | `paper_carton` | 紙盒 / 利樂包 |
| 3 | `glass_bottle` | 玻璃瓶 |

## 場景

- 輸送帶 + **俯拍 RGB 相機**，相機裝在手臂的**上游**。皮帶速度 **0.15 m/s**。
- 手臂：**UR10 + 吸盤**（Isaac Sim Surface Gripper）。
- 收集桶：4 個類別桶，皮帶**兩側各 2 個**。皮帶末端再一個桶，收所有沒被撿走的東西
  （信心不足、漏掉、吸取失敗）→ 用來算「**漏撿率（miss rate）**」。

## 動態取物（皮帶不停）

1. 相機在上游看到物體。
2. 感知輸出：類別 + mask + 吸取點。
3. 像素 → 皮帶座標：相機校正 + 皮帶平面高度 + **各類別已知厚度**。
4. 用「皮帶速度 × 時間差」預測物體未來位置。
5. UR10 以皮帶速度跟著物體移動並吸取。
6. 放進該類別的桶子。

## 感知

- Ultralytics YOLO **實例分割**（`-seg`，n 或 s 版）。**只用 RGB，不用深度。**
- 吸取點 = mask 內**離邊緣最遠的點**（distance transform）。

## 特權資訊規則（重要）

- 最終流程**只能用相機影像**（加上皮帶速度，真實系統會由編碼器提供）。
- **絕對不能**從模擬器讀物體的位置或類別。
- 例外：開發模式 `--perception gt` 會讀真值位置，讓手臂開發可以在模型完成前進行。
- 預設 / 最終模式是 `--perception yolo`。兩者的切換只有**一個乾淨的接縫**
  （`trash_sorter/perception.py` 的 `Perception` 介面）。

## 合成資料

- Isaac Sim Replicator 產生影像，**自動產生**實例分割標籤，匯出成 YOLO-seg 格式。
- Domain randomization（領域隨機化）：
  - 物體姿態與數量（1–4 個，可輕微重疊）
  - 燈光強度、色溫、方向
  - 皮帶顏色 / 材質
  - 相機高度 / 角度小幅抖動
  - 物體材質 / 顏色抖動

## 3D 資產

- 團隊每類收集 **10–20 個網路模型**（Objaverse / Sketchfab）+ 手機掃描。
- 玻璃瓶與鋁罐用網路模型，套上玻璃 / 金屬材質。
- 資產處理（縮放到真實尺寸、置中、指定材質、轉 USD）必須是**批次 Python 腳本**，
  團隊不手動編輯模型。
- 真實模型到位前，先用**程序化產生的替代資產**（圓柱 / 方塊，尺寸與材質大致正確，每類多種變化）。

## 真實測試集（由人完成，程式提供工具）

- 約 **300 張測試照片**：直到最後評估前**完全不碰**。
- 另外 **50–100 張微調照片**（和測試照片不同）。
- 用 CVAT / Roboflow 標註，匯出 YOLO-seg 格式。

## 實作補充（v1 做的決定）

這些是寫程式時做的細節決定，不改變上面的設計：

- **追蹤器**：同一個物體會在相機裡出現很多幀。追蹤器把它們合成一個 track，
  並用這些觀測**擬合每個物體自己的速度**（圓的瓶罐在皮帶上會滾、會滑，速度不完全等於皮帶速度）。
  只用相機資料，不違反特權資訊規則。
- **手臂控制**：UR10 用**解析解逆運動學**（`trash_sorter/ur10.py`，和 Isaac Sim 的模型比對過，誤差 < 1 µm），
  吸盤尖端位置有速度與加速度限制，放開前先停穩，避免把東西甩出桶外。
- **計分**：模擬器在「計分」時會讀物體最後落在哪個桶（這是評估，不是感知），
  `--perception yolo` 時取物流程本身完全沒用到真值。
- 圓柱在模擬中會一直滾，真實的凹瓶不太會，所以模擬物體加了角阻尼（`scene.py`）。
